# 企业行政资料管理系统压缩包使用流程

## 一、这个压缩包是什么

这个压缩包是企业行政资料管理系统的完整备份包，适合用于：

1. 当前电脑备份保存。
2. 项目损坏后的恢复。
3. 迁移到另一台电脑或服务器运行。
4. 交给技术人员继续开发或部署。

压缩包不是普通安装包，它包含源码、部署配置、数据库备份、上传文件和桌面应用安装程序。

## 二、压缩包内容说明

解压后通常包含以下内容：

```text
企业行政资料管理系统_完整项目备份_xxxx/
├─ project/                     项目源码、Docker 配置、脚本、上传文件
├─ database-backup/             PostgreSQL 数据库备份
│  └─ admin_docs_prod_latest.dump
├─ desktop-installer/           桌面应用安装程序和便携版
├─ 备份说明.txt
└─ 压缩包使用流程.md
```

其中最重要的是：

```text
project/data/storage
```

这里保存系统中已经上传的真实文件。

数据库备份在：

```text
database-backup/admin_docs_prod_latest.dump
```

数据库保存分类、标签、文件记录、版本记录、用户等结构化数据。

## 三、只作为备份保存时怎么用

如果只是想留一份备份，不需要做任何操作。

直接保存这个 `.zip` 文件即可。

建议至少额外复制一份到：

1. 移动硬盘。
2. NAS。
3. 公司内部服务器。
4. 其他安全存储位置。

注意：压缩包里包含 `.env.production`，里面有数据库密码和系统密钥，不要随便发给无关人员。

## 四、迁移到新电脑前需要安装什么

新电脑需要先安装：

1. Docker Desktop。
2. Node.js。
3. pnpm。

如果只是运行系统，核心是 Docker Desktop。

如果还要继续开发或重新构建前后端，则需要 Node.js 和 pnpm。

## 五、在新电脑上启动系统

### 1. 解压压缩包

把压缩包解压到一个路径，例如：

```text
D:\admin-docs-backup
```

进入解压后的：

```text
project
```

### 2. 打开 PowerShell

在 `project` 文件夹空白处按住 Shift 并点击鼠标右键，选择：

```text
在此处打开 PowerShell 窗口
```

或者手动进入目录：

```powershell
cd D:\admin-docs-backup\企业行政资料管理系统_完整项目备份_xxxx\project
```

### 3. 启动 Docker 服务

执行：

```powershell
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build
```

等待服务启动完成。

### 4. 检查服务状态

执行：

```powershell
docker compose --env-file .env.production -f docker-compose.prod.yml ps
```

正常情况下会看到三个服务：

```text
admin-docs-prod-postgres
admin-docs-prod-backend
admin-docs-prod-frontend
```

状态应为 `healthy` 或 `Up`。

### 5. 浏览器访问系统

打开浏览器访问：

```text
http://localhost:8080
```

管理员账号由 `.env.production` 配置：

```text
账号：ADMIN_USERNAME 对应的值
密码：ADMIN_PASSWORD 对应的值
```

## 六、恢复数据库备份

如果新电脑是第一次运行，需要导入数据库备份。

确保 Docker 服务已经启动后，在 `project` 目录执行：

```powershell
docker cp ..\database-backup\admin_docs_prod_latest.dump admin-docs-prod-postgres:/tmp/admin_docs_prod_latest.dump
```

然后执行：

```powershell
docker exec -it admin-docs-prod-postgres pg_restore -U admin_docs_prod -d admin_docs_prod --clean --if-exists --no-owner --no-privileges /tmp/admin_docs_prod_latest.dump
```

恢复完成后重启服务：

```powershell
docker compose --env-file .env.production -f docker-compose.prod.yml restart
```

再次访问：

```text
http://localhost:8080
```

## 七、上传文件如何恢复

系统上传的真实文件已经在：

```text
project/data/storage
```

迁移时必须保留这个目录。

数据库和 `data/storage` 必须一起恢复：

1. 只有数据库，没有 `data/storage`：系统能看到文件记录，但下载或预览会失败。
2. 只有 `data/storage`，没有数据库：系统不知道这些文件属于哪个分类、哪个版本。

## 八、桌面应用怎么使用

进入：

```text
desktop-installer
```

可以选择安装：

```text
企业行政资料管理系统 安装程序 0.1.0.exe
```

也可以使用便携版：

```text
企业行政资料管理系统 便携版 0.1.0.exe
```

注意：桌面应用只是系统入口，仍然需要 Docker 服务已经启动。

推荐顺序：

```text
1. 先启动 Docker 服务
2. 确认 http://localhost:8080 可以访问
3. 再打开桌面应用
```

## 九、常用命令

### 启动系统

```powershell
docker compose --env-file .env.production -f docker-compose.prod.yml up -d
```

### 停止系统

```powershell
docker compose --env-file .env.production -f docker-compose.prod.yml down
```

### 查看服务状态

```powershell
docker compose --env-file .env.production -f docker-compose.prod.yml ps
```

### 查看日志

```powershell
docker compose --env-file .env.production -f docker-compose.prod.yml logs -f
```

### 重新构建并启动

```powershell
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build
```

## 十、局域网给其他人访问

如果系统部署在公司一台固定电脑上，其他人在同一局域网内可以通过这台电脑的 IP 访问。

例如服务器电脑 IP 是：

```text
192.168.1.50
```

正式多人使用时，其他电脑应通过 HTTPS 反向代理访问：

```text
https://admin.example.internal
```

如果无法访问，需要检查：

1. Docker 服务是否启动。
2. Windows 防火墙是否允许 8080 端口。
3. `.env.production` 中 `ALLOWED_ORIGINS` 是否加入对应地址。

例如：

```text
ALLOWED_ORIGINS=http://localhost:8080,http://127.0.0.1:8080,https://admin.example.internal
```

生产启动脚本会拒绝非本机 HTTP 来源。尚未配置 HTTPS 前，只建议在部署电脑本机访问；配置 HTTPS 反向代理后，再在 Windows 防火墙中放行代理使用的 HTTPS 端口。

修改后重启服务：

```powershell
docker compose --env-file .env.production -f docker-compose.prod.yml restart
```

## 十一、注意事项

1. 不要随意删除 `project/data/storage`。
2. 不要随意删除 `project/data/postgres`。
3. 不要把包含 `.env.production` 的压缩包发给无关人员。
4. 如果迁移到新电脑，数据库备份和上传文件目录必须一起迁移。
5. 桌面应用不是独立数据库程序，后台 Docker 服务必须运行。
6. 多人使用前必须为管理员设置独立强密码，不得继续使用示例密码。

## 十二、推荐恢复顺序

最稳妥的恢复顺序如下：

```text
1. 安装 Docker Desktop
2. 解压压缩包
3. 进入 project 目录
4. 执行 docker compose 启动系统
5. 导入 database-backup 数据库备份
6. 确认 project/data/storage 存在
7. 重启 Docker 服务
8. 打开 http://localhost:8080
9. 登录管理员账号
10. 可选安装桌面应用
```
