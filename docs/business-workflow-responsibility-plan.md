# 项目与事项责任闭环实施计划

## 目标

让每个事项都能明确回答：谁负责、当前状态、下一步动作、截止时间、谁审批、谁付款、谁完成，以及发生过哪些变化。

## 阶段一：责任基础版（已完成）

- 跟进任务增加进度、完成说明、取消原因、开始时间、完成/取消人员。
- 借款与报销增加申请人、经办负责人、审批人、付款人、结算负责人。
- 服务端限制财务状态流转，并记录审批、付款、结算人员和时间。
- 任务完成和取消需要责任人或管理员操作，并保留结果说明。
- 工作台增加按“我的任务”和“未分配任务”查看的能力。

补充规则：

- 新建任务默认归属事项负责人；普通员工只能把任务分配给自己，管理员可以指定任意启用员工。
- 任务完成或取消时必须由任务负责人或管理员操作，并填写完成说明或取消原因；系统保存实际完成人/取消人及时间。
- 新建借款或报销默认将当前用户写入申请人和经办负责人；管理员可以补充或调整申请人、经办、审批、付款和结算负责人。
- 审批、付款、结算等状态流转由服务端校验责任人；普通员工只能执行分配给自己的动作，管理员可以处理全部记录。

验收：创建任务或财务记录后可看到责任人；非法状态跳转被拒绝；完成、审批、付款、结算都有人员和时间；旧数据仍可读取。已通过后端测试、真实 API 烟测和 Docker 数据库迁移验收。

## 阶段二：过程跟进版（已完成）

- 新增人工跟进记录，支持跟进方式、结果、下一步动作、下一位责任人和下次跟进日期。
- 事项详情展示责任摘要、逾期任务、待处理财务记录和最近一次跟进。
- 工作台展示待跟进和逾期风险。

补充规则：

- 人工跟进保留跟进人、方式、内容、结果和下一步动作。
- 填写下一次跟进日期时必须指定下一责任人；普通员工只能指定自己，管理员可以指定任意启用员工。
- 下一责任人和日期会进入工作台的待跟进、逾期和 7 天内提醒统计。

验收：一条跟进记录可以完整描述一次业务推进，并能形成下一次责任提醒。已通过下一责任人必填和普通员工越权分配的回归测试。

## 阶段三：审计统计版（已完成）

- 操作记录保留修改前后差异和状态变化。
- 责任人变更可追溯。
- 按员工统计任务、借款、报销、逾期和待办。
- 支持按期间导出责任报表。

补充规则：

- 事项、任务、合同、借款、报销、凭证关联和人工跟进的关键操作均写入不可由业务界面编辑的操作记录。
- 操作记录包含操作人、时间、对象、关联事项、摘要以及修改前后差异或快照；责任人变化可追溯。
- 管理员可按员工、开始日期和结束日期查询责任统计，并导出 UTF-8 CSV；普通员工不能访问责任报表接口。

验收：管理员可以按人员和期间查看责任数据，并导出可交付的 CSV 报表；普通用户不能修改或删除审计记录。已通过责任报表查询、CSV 导出和管理员权限验收。

## 迁移与兼容

- `20260909150000_add_business_responsibility_fields` 增加任务完成/取消责任字段和财务责任字段，并为旧记录保留可读取的兼容默认值。
- `20260909160000_add_business_follow_ups` 增加人工跟进表、跟进方式枚举和后续责任索引。
- 操作记录复用现有业务活动表，通过 `metadata` 保存对象 ID、快照和字段差异，不复制文件中心的真实文件。
- 本阶段仍保持单企业数据空间；多租户隔离、外部通知和审批流不在当前范围。
