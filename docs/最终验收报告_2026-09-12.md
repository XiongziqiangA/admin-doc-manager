# 行政资料管理系统与资产设备管理系统合并项目最终验收报告

## 1. 验收结论

本项目已完成“行政资料管理系统 + 资产设备管理系统”的统一平台合并基础建设。行政资料管理原有业务能力保留，并与项目事项、财务归集、资产台账、资产流转、审批、通知和可选 AI 能力统一到同一套 PostgreSQL、认证、附件和前端工作台中。

在当前合并分支、隔离 PostgreSQL、源码构建运行环境和 Docker Compose 隔离环境中，核心业务、接口、迁移、备份恢复、构建和依赖安全门禁均通过。本报告的结论是：

> **源码交付和隔离验收通过，可以进入目标服务器部署准备；公网或公司正式多人使用仍需按第 9 节完成生产环境配置。**

本次验收没有对真实生产数据库执行迁移 `--apply`，也没有修改旧资产系统和现有生产数据。

## 7. 安全和部署硬化

- 生产 Compose 对 PostgreSQL、后端和前端设置了内存/CPU 上限。
- 后端和前端启用 `no-new-privileges`；后端、前端使用只读根文件系统和临时文件系统。
- 生产启动脚本校验数据库密码、JWT 密钥、管理员密码、默认管理员名和来源地址。
- 本机 `localhost`/`127.0.0.1`/`::1` 可以使用 HTTP；非本机生产来源必须使用 HTTPS。
- PostgreSQL 和后端不直接暴露给宿主机，默认只暴露前端入口。
- `data/postgres` 与 `data/storage` 必须同时备份。
- `xlsx` 已替换为 `ExcelJS`，当前生产依赖审计无高危及以下漏洞。
- `.env.production`、API Key、数据库密码、JWT 密钥不会纳入源码提交。

特别提醒：检查历史本地生产镜像时发现，旧镜像环境元数据曾可能包含 API、数据库、管理员或 JWT 类敏感配置。正式上线前应统一轮换曾在旧镜像或旧环境中使用过的 API Key、数据库密码、管理员密码和 JWT 密钥，即使当前干净镜像已经不再包含它们。

## 8. 已知边界

- 当前是单企业部署模型；后续多企业需要增加租户边界、租户管理员和跨租户数据策略。
- AI 语义检索和财务智能归集默认关闭；没有有效 API Key 时，普通关键词和正文索引检索仍可用。
- AI 只生成建议，不能自动修改正式分类、源文件或交付包；交付前仍需人工确认。
- 生产环境的真实迁移 `--apply` 本次未执行，需要在目标服务器完成备份、dry-run、审批和正式迁移。
- HTTPS 证书、DNS、Windows 防火墙和公司网络入口需要按目标服务器实际情况配置。
- 前端构建仍有主 JavaScript 包超过 500KB 的非阻断提示，后续可通过代码分包继续优化首屏加载。
- 当前不包含完整会计核算、报销审批链、自动付款、还款明细和外部通知平台对接。

## 9. 目标服务器上线清单

1. 安装并启动 Docker Desktop 或 Linux Docker Engine。
2. 将项目复制到目标服务器，确认 `data/postgres` 和 `data/storage` 的读写权限。
3. 复制 `.env.production.example` 为 `.env.production`，填写新的数据库密码、JWT 密钥、管理员账号和管理员密码。
4. 配置 HTTPS 反向代理和证书，将对外来源写入 `ALLOWED_ORIGINS`；不要把非本机 HTTP 直接作为多人入口。
5. 先执行 `scripts/start-prod.ps1 -Build`，确认三个容器 healthy。
6. 创建首次完整备份，并在非生产副本上验证恢复。
7. 使用管理员创建员工账号并按公司流程分配使用范围。
8. 如需迁移旧资产数据，先执行 dry-run，审核报告后再使用 `--apply` 和 `--copy-files`。
9. 设置定期数据库和文件备份，并将备份复制到独立存储位置。
10. 上线后检查登录、文件上传/下载、分类、搜索、财务归集、事项和资产流转主流程。
