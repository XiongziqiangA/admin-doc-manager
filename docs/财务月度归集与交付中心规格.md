# 财务月度归集与交付中心规格

## 目标

在不改变现有文件分类、标签、版本和存储方式的前提下，新增独立的月度财务归集工作台。用户可以把系统内已有文件按人员、项目或报销事项重新分组，并导出与“我界报销单(打包）.zip”相同类型的目录结构。

第一版面向当前单企业的管理员和员工，所有已登录用户均可使用。系统默认使用本地规则推荐；管理员配置 OpenAI 兼容中转站后，可按需启用财务智能识别。AI 只生成待确认建议，最终分组和导出仍由用户人工确认，不新增审核流程。

## 技术栈与命令

- 后端：NestJS、Prisma、PostgreSQL、Vitest
- 前端：React、TypeScript、Ant Design、Vite
- 桌面端：Electron，继续复用当前 Web 前端
- 后端测试：`pnpm --filter backend test`
- Prisma 校验：`pnpm --filter backend prisma:validate`
- 类型检查：`pnpm -r typecheck`
- 全量构建：`pnpm -r build`
- 本地生产启动：`docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build`

## 数据模型

### FinancePackageTask

- `id`：任务 ID
- `name`：任务名称
- `period`：归属月份，格式 `YYYY-MM`
- `rootFolderName`：ZIP 内总目录名称
- `status`：`DRAFT`、`READY`、`EXPORTED`
- `includeManifest`：是否生成 `文件清单.xlsx`
- `createdById`、`createdAt`、`updatedAt`、`lastExportedAt`

### FinanceAnalysisJob 与 FinancePackageSuggestion

- `FinanceAnalysisJob`：异步识别任务、处理进度、模型信息、请求次数、token 用量和耗时。
- `FinancePackageSuggestion`：按文件保存 AI 或规则生成的材料类型、结构化字段、事项目录、导出文件名、置信度和处理状态。
- 识别建议在人工确认前不会创建交付目录、加入归集文件或修改正式分类；确认时可选择已有目录、总目录、修改建议目录，或暂不处理。

### FinancePackageGroup

- `id`、`taskId`
- `name`：事项或人员文件夹名称
- `parentId`：支持后续多级目录；第一版界面以一级事项组为主
- `sort`：目录顺序

### FinancePackageItem

- `id`、`taskId`、`groupId`
- `documentId`、`versionId`：加入时锁定具体版本
- `materialType`：报销单、发票、付款单、车票、合同、其他凭证
- `exportFileName`：允许只修改本次导出的文件名
- `sort`、`remark`

同一任务中的一个文件默认只能加入一次。文件可以在不同月份或不同任务中重复使用。删除任务只删除归集关系，不删除原文件。

## API 契约

- `GET /api/finance-packages`：任务列表
- `POST /api/finance-packages`：创建任务，可复制已有任务的目录结构
- `GET /api/finance-packages/:id`：任务、目录、文件和校验结果
- `PATCH /api/finance-packages/:id`：修改任务名称、月份、总目录和清单设置
- `DELETE /api/finance-packages/:id`：删除任务，不影响原文件
- `POST /api/finance-packages/:id/groups`：创建事项文件夹
- `PATCH /api/finance-packages/:id/groups/:groupId`：重命名或排序
- `DELETE /api/finance-packages/:id/groups/:groupId`：删除空目录；非空时拒绝
- `GET /api/finance-packages/:id/candidates`：规则推荐候选文件
- `POST /api/finance-packages/:id/items`：批量加入文件并锁定当前版本
- `PATCH /api/finance-packages/:id/items/:itemId`：移动分组、修改材料类型或导出名称
- `DELETE /api/finance-packages/:id/items/:itemId`：从任务移除，不删除原文件
- `GET /api/finance-packages/ai/status`：查看财务 AI 开关、模型和中转站状态，不返回 API Key
- `POST /api/finance-packages/:id/analysis`：创建异步财务识别任务，可分批传入文件 ID
- `GET /api/finance-packages/:id/analysis/:jobId`：查询识别进度和人工确认建议
- `POST /api/finance-packages/:id/analysis/:jobId/confirm`：提交人工修改、确认或暂不处理结果
- `GET /api/finance-packages/ai/config`：管理员查看 AI 配置状态，不返回 API Key 原文
- `PATCH /api/finance-packages/ai/config`：管理员保存或更新 OpenAI 兼容中转站配置
- `POST /api/finance-packages/ai/config/test`：管理员测试中转站连接，不读取财务文件
- `POST /api/finance-packages/:id/export`：校验并流式生成 ZIP

所有输入在 DTO 边界校验；沿用现有 JWT、响应封装和错误处理，不修改原 `/api/documents/export` 契约。

## 页面与交互

主导航新增“财务归集”。页面采用工作台结构：顶部为月份、任务状态和导出操作；左侧为事项目录；右侧为当前目录文件；候选文件使用抽屉批量加入。页面不依赖横向滚动，文件名称和材料类型优先展示，版本、分类等详细信息在详情区域查看。

支持：

1. 新建月度任务并设置总目录名称。
2. 从上月复制目录结构，但不复制文件。
3. 按月份、财务分类、文件名关键词、标签和正文关键词推荐候选文件。
4. 批量加入、移动、移除文件。
5. 修改本次导出文件名并标记材料类型。
6. 显示未分组、源文件缺失、已有新版本和同目录重名警告。
7. 预览或下载原文件。
8. 导出 ZIP；嵌套 ZIP 作为普通文件原样保留。

## 导出规则

- ZIP 文件名默认为 `{任务名称}_{YYYYMMDD}.zip`。
- ZIP 内所有内容位于 `rootFolderName/` 下。
- 未分组文件直接放在总目录下，以兼容样例中的“陈曦提交的备用金.pdf”。
- 默认采用原始上传文件名；用户设置 `exportFileName` 时优先使用设置值。
- 同一目录重名自动追加 ` (2)`、` (3)`，并在清单记录最终名称。
- 清理 Windows 非法字符，阻止路径穿越，限制单个路径段长度。
- 中文路径使用 UTF-8 标志。
- 只导出任务记录的 `versionId`；存在新版本时提示但不静默替换。
- 可选生成 `rootFolderName/文件清单.xlsx`。
- 文件始终从原存储位置流式读取，不移动、不复制、不修改源文件。

## 测试策略

- 纯函数单元测试：目录清理、路径生成、重名处理、材料类型推断、校验结果。
- 服务测试：创建任务、复制目录、加入版本快照、非空目录删除、导出条目生成。
- 契约与类型检查：DTO、Prisma Client、前后端类型。
- 端到端烟测：创建任务、创建分组、加入文件、导出 ZIP，检查中文路径、原文件字节和清单。
- 浏览器验收：任务空状态、创建流程、批量加入、文件移动、导出操作，无控制台错误和横向滚动。

## 边界

- 始终：保持旧接口兼容；校验用户输入；记录任务创建者和导出时间；测试后再进入下一阶段。
- 本次允许：新增 Prisma 模型和迁移；新增后端模块、前端页面和 API；使用 `ExcelJS` 生成中文清单，避免引入存在安全风险的旧 `xlsx` 依赖。
- 本次不做：AI 自动确认归集、财务审核、代账公司直接发送、多企业隔离、嵌套 ZIP 解包重组。
- 永不：修改或删除源文件；把 AI 建议直接写回正式分类树；在未启用并确认外发边界的情况下把财务文件内容发送到外部服务。

## 验收标准

1. 能生成一个总目录、至少 21 个自定义事项目录、40 个 PDF 和一个嵌套 ZIP 的交付包。
2. 中文目录和文件名在 Windows 解压后正常显示，所有导出文件与源版本校验值一致。
3. 未分组文件能直接位于总目录，分组文件位于对应事项目录。
4. 同目录重名不会覆盖，非法名称不能逃逸总目录。
5. 文件更新后任务提示新版本，默认仍导出已锁定版本。
6. 可选择是否生成 Excel 清单。
7. 删除归集任务或移除条目不会改变文件中心中的任何文件。
8. 原上传、分类、搜索、版本、回收站和批量导出测试全部继续通过。
