# 项目追踪升级路线

## 目标

将现有的“项目与事项”从资料关联和任务记录，逐步升级为适合行政项目使用的轻量项目追踪工具。第四优先级的消息通知暂不纳入本轮范围。

## 第一阶段：项目进度基础

### 范围

- 项目阶段：名称、顺序、状态、负责人、起止日期和进度。
- 里程碑：名称、所属阶段、负责人、截止日期和完成状态。
- 任务可以关联到阶段和里程碑。
- 项目整体进度实时计算：优先按阶段计算；没有阶段时按任务计算。
- 项目健康度：正常、需关注、已延期、已完成、已取消、暂无计划。
- 项目详情展示阶段、里程碑、整体进度和健康度。

### 进度规则

1. 有阶段时，项目进度为各阶段进度的平均值。
2. 阶段有任务时，阶段进度为所属任务进度的平均值；没有任务时使用阶段手工进度。
3. 没有阶段但有任务时，项目进度为任务进度的平均值。
4. 没有阶段和任务时，项目进度为 0%；项目状态为已完成时显示 100%。
5. 已取消项目显示已取消；已完成项目显示已完成。
6. 活跃项目存在已过期的未完成任务、未完成里程碑或项目结束日期已过期时，健康度为已延期。
7. 没有延期但项目结束日期或未完成里程碑在 7 天内到期时，健康度为需关注。

### 验收标准

- 管理员可以在项目详情中新增、编辑、删除阶段和里程碑。
- 新建或编辑任务时可以选择所属阶段和里程碑。
- 项目详情明确显示整体进度、阶段进度、里程碑完成情况和健康度。
- 项目列表可以显示整体进度和健康度。
- 进度和健康度由服务端实时计算，刷新后结果一致。
- 旧项目、旧任务和旧文件关联无需迁移人工数据即可继续使用。

## 第二阶段：风险与问题

### 范围

- 问题/风险登记：标题、类型、描述、严重程度、责任人、状态、截止日期、解决方案。
- 支持系统账号和自定义责任人。
- 支持关联多个文件和操作记录。
- 项目详情展示未解决风险、逾期问题和处理进展。

### 第二阶段验收结果

- 已完成风险/问题统一登记模型，支持类型、严重程度、状态、责任人、截止日期和解决方案。
- 已完成风险/问题新增、编辑、状态流转、软删除和操作记录。
- 已完成风险/问题多附件上传、查看和取消关联，取消关联不删除文件中心源文件。
- 项目详情已显示未解决、高危/紧急、逾期等统计，并支持按类型、状态和严重程度筛选。
- 已通过后端单元测试、类型检查、构建、前端类型检查和构建。
- 已在 Docker 生产栈中应用迁移并完成登录、列表、新增、解决、删除接口烟测。

## 第三阶段：项目可视化

### 范围

- 项目看板：按项目状态或阶段状态查看。
- 项目时间线：展示项目、阶段、里程碑、任务和合同节点。
- 项目详情提供列表、看板、时间线切换。
- 保持现有列表查询、文件关联、业务跟踪和财务功能不变。

## 暂不实现

- 邮件、企业微信、桌面推送等通知功能。
- 复杂甘特图和关键路径计算，除非后续使用规模证明有必要。
