# 项目与事项中心规格

## 1. 目标

在不改变文件中心正式分类、标签、版本、回收站和真实存储方式的前提下，增加业务事项维度，用于把合同、项目、借款、报销、采购等日常行政业务串联起来。

文件分类和业务关联是两个独立维度：

```text
文件分类：财务票据 / 合同文件 / 行政制度
业务关联：2026 年市场推广项目 / 市场推广合同 / 项目借款
```

## 2. 第一阶段范围

### 事项类型

| 枚举值 | 页面名称 |
| --- | --- |
| `PROJECT` | 项目 |
| `CONTRACT` | 合同 |
| `REIMBURSEMENT` | 报销 |
| `LOAN` | 借款 |
| `PROCUREMENT` | 采购 |
| `OTHER` | 其他事项 |

### 事项状态

| 枚举值 | 页面名称 |
| --- | --- |
| `PLANNING` | 筹备中 |
| `IN_PROGRESS` | 进行中 |
| `COMPLETED` | 已完成 |
| `CANCELLED` | 已取消 |

### 事项字段

- 系统生成的唯一事项编号、事项名称、类型和状态。
- 可选父级事项，用于形成多级业务关系。
- 负责人、创建人、所属部门和合作单位。负责人、部门和合作单位均支持选择标准主数据或填写当前事项的自定义名称。
- 自定义名称只保存在当前事项，不会自动创建或修改部门、合作单位主数据；负责人自定义名称只用于业务展示，系统权限负责人仍由内部用户账号关联控制。
- 开始日期、结束日期、可选金额和备注。
- 创建时间、更新时间和软删除时间。

## 3. 数据模型

新增 `BusinessMatter` 和 `BusinessMatterDocument` 两个模型。

```text
BusinessMatter 1 ---- N BusinessMatterDocument N ---- 1 Document
       |
       +---- parent / children（自关联上下级）
```

事项删除只更新 `deletedAt`。取消文件关联只删除关联表记录；两种操作都不能删除 `Document`、`DocumentVersion` 或 `data/storage` 中的真实文件。

文件关联表的 `(matterId, documentId)` 为唯一键，防止同一文件在同一事项下重复出现。关联可记录 `relationType` 和 `isPrimary`，第一阶段页面默认使用 `REFERENCE` 关联类型。

## 4. API

所有接口都需要 JWT Bearer Token，统一前缀为 `/api`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/business-matters` | 分页列表和筛选 |
| `POST` | `/business-matters` | 新建事项 |
| `GET` | `/business-matters/:id` | 事项详情、上下级和关联文件 |
| `PATCH` | `/business-matters/:id` | 编辑事项 |
| `DELETE` | `/business-matters/:id` | 软删除事项 |
| `POST` | `/business-matters/:id/documents` | 批量关联已有文件 |
| `DELETE` | `/business-matters/:id/documents/:documentId` | 取消文件关联 |

列表支持 `keyword`、`type`、`status`、`parentId`、`ownerId`、`departmentId`、`partnerId`、`documentId`、分页和排序参数。所有筛选只查询未软删除事项。

## 5. 权限边界

- 员工和管理员都可以查看事项和关联文件。
- 员工可以创建事项；事项创建后，创建人或负责人可以编辑、删除和维护文件关联。
- 管理员可以编辑、删除和维护全部事项。
- 使用标准主数据时，负责人只允许使用有效员工，部门和合作单位只允许使用未删除的有效记录。
- 使用自定义名称时，服务端会校验长度并保证同一字段不会同时提交标准主数据和自定义名称。
- 服务端校验父级事项存在，并拒绝自身引用和任何循环父子链。
- 关联文件必须是文件中心中存在且未删除的文件，重复关联直接返回冲突错误。

## 6. 页面验收标准

- 登录后左侧导航出现“项目与事项”。
- 列表显示事项名称/编号、类型、状态、负责人、关联文件数量和最近更新时间。
- 可以按关键词、类型和状态筛选，并通过分页浏览超过一页的数据。
- 新建事项可以保存顶级事项；选择上级事项后可以建立子事项。
- 新建或编辑事项时，负责人、所属部门和合作单位可以切换为自定义输入；切换回标准主数据后会清除当前事项的自定义名称。
- 事项详情可以看到基本信息、上级事项、子事项和关联文件。
- 关联文件弹窗可以搜索、批量选择和关联现有文件，不产生文件副本。
- 详情中的文件可以进入现有文件详情流程；取消关联不影响文件中心。
- 删除事项后事项从列表消失，关联文件仍可在文件中心查看和下载。
- 原文件上传、版本更新、分类管理、回收站、财务归集和 AI 配置功能回归正常。

## 7. 后续阶段

第一阶段不实现还款明细、报销核销、合同到期提醒、复杂审批、完整会计核算或 AI 自动建立正式关系。后续如需实现，应在本模型基础上增加独立业务明细表和可审计的状态流转，不直接把这些字段继续堆入 `Document`。
